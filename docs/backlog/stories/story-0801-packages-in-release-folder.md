# STORY-0801: Packages a stranger can install, built into `release/`

- Epic: [epic-m8-release.md](../epic-m8-release.md)
- Status: Ready
- Size: M

## Goal

Produce, from the release build, a portable ZIP for Windows and a `.tar.gz` and
`.deb` for Linux, each carrying the two user-facing binaries, `LICENSE`, the man
pages and a checksum file — written to `release/` at the repository root, and
verified by installing the `.deb` and running the installed binary rather than by
producing a file.

## Design references

- [epic-m8](../epic-m8-release.md) — what the package holds and why an archive is
  an honest deliverable.
- [versioning.md](../../versioning.md) — from 1.0 the CLI surface and the on-disk
  output layout bind; the package is how a stranger meets both.
- [M5](../epic-m5-performance.md) introduced the `Release build (artifact)` CI
  job. This story consumes that build rather than adding one of its own.

## Measured before writing (2026-08-08)

Two claims the epic makes did not survive contact with the tree, and one it does
not make matters more than either.

- **There is no `install()` rule anywhere**, and no `CPack` include. Packaging
  starts from zero, not from a target that needs pointing somewhere.
- **The `cli` feature in `vcpkg.json` declares a dependency on CLI11 that no file
  in `src/` or `include/` mentions.** The epic's "only third-party dependency is
  GoogleTest, which is test-only" is true of what is *compiled*, and false of what
  the manifest *declares*. A package built from a manifest that names a library
  the code does not use is a package whose dependency list is already wrong.
- **Nothing sets `CMAKE_MSVC_RUNTIME_LIBRARY`**, so Windows binaries link the
  dynamic CRT and a "portable ZIP" does not run on a machine without the Visual
  C++ redistributable. The epic does not mention this. The person unpacking that
  ZIP is a stranger trying to recover their photographs, and a missing DLL is
  indistinguishable from a broken tool.
- The `Release build (artifact)` job hand-copies three binaries and
  `build-info.json` into `dist/` and uploads a workflow artifact with
  `retention-days: 14`. It expires, and it is not a release.
- The `release` preset builds `RelWithDebInfo`, so the binaries carry debug info.

## Design decisions

**Packages are written to `release/` at the repository root**, via
`CPACK_PACKAGE_DIRECTORY`, and `.gitignore` gains `/release/`. One predictable
directory is what story-0803's tag-triggered workflow uploads from; today the
release build scatters into a build tree alongside several hundred log files.

**`release/` and `build/release/` are different things and the story says so
once, here.** `build/release/` is the CMake build tree for the `release` preset;
`release/` holds finished packages and nothing else. Nothing in the repository
should ever write to both.

**Windows links the static CRT** (`CMAKE_MSVC_RUNTIME_LIBRARY` set to
`MultiThreaded`), because that is what makes the word "portable" in "portable
ZIP" true. The acceptance criterion is the one that proves it: the binary runs on
a Windows machine with no redistributable installed.

**Two binaries ship: `revenant-undelete` and `revenant-carve`.**
`revenant-imagegen` generates test fixtures and stays out of the user package —
shipping it invites someone to write an image while trying to read one.

**The `.deb` gets real `install()` rules** over `GNUInstallDirs`, so the archive
and the package are two renderings of one install tree rather than two hand-kept
copies of a file list. This is the same shape story-0702 applied to the flag
table and the audit found missing in the gate wiring.

**Checksums cover the package files**, are generated by CPack rather than by a
hand-run command, and name the algorithm in the file.

**The stale CLI11 feature is removed from `vcpkg.json`** as part of this story.
Packaging is when a dependency list stops being a note and becomes a claim.

**Code signing is out of scope and the release notes say so** — an unsigned
binary that admits it is unsigned is honest; one that stays quiet leaves the user
to discover a SmartScreen warning alone.

**story-0802 lands before this one.** The package carries man pages, and
story-0802 writes them; the numbers are labels, not an execution order. This
story's man-page criterion cannot be observed until they exist.

## Acceptance criteria

- [ ] `cmake --build --preset release --target package` writes to `release/` and
      nowhere else; `/release/` is in `.gitignore`.
- [ ] The Windows ZIP holds `revenant-undelete.exe`, `revenant-carve.exe`,
      `LICENSE`, the man pages and a checksum file, and no other executable.
- [ ] The Linux `.tar.gz` and `.deb` hold the same set, with binaries under
      `bin/` and man pages under `share/man/man1/` per `GNUInstallDirs`.
- [ ] A Windows binary from the ZIP runs on a machine with no Visual C++
      redistributable installed.
- [ ] `dpkg -i` installs the `.deb`, `revenant-undelete --help` runs from `PATH`,
      and `dpkg -r` removes every file it added.
- [ ] `man revenant-undelete` renders from the installed package.
- [ ] Every checksum in the checksum file verifies against its package.
- [ ] `vcpkg.json` declares no dependency the tree does not use.
- [ ] The `.deb` declares no runtime dependency beyond libc and libstdc++, and
      `ldd` on the installed binary names nothing else.

## Test plan

- **Unit** — none. Packaging has no logic worth a unit test, and a test that
  asserted a CMake variable would pass without a package ever being built.
- **Integration, on the Linux bench** — build the release preset, run `package`,
  then in one script: verify checksums, `dpkg -i`, run the installed binary
  against a generated fixture image and compare the recovered file's SHA-256
  against the source, `man revenant-undelete`, `dpkg -r`, and assert the install
  tree is empty afterwards. This is the criterion the epic states as "installed
  and run from the package rather than from a build tree", and it fails if any
  step is skipped.
- **Integration, on Windows** — unpack the ZIP into a directory that is not the
  build tree, run `revenant-carve` there against a fixture image, and compare
  the recovered bytes. The no-redistributable check is a separate manual step
  recorded in the story on completion, because CI runners have the runtime
  installed and cannot observe its absence.
- **Content assertion** — a test lists each package's contents and fails on an
  unexpected entry, so a stray `revenant-imagegen` or a `.pdb` cannot arrive
  unnoticed. Assert the shape, not today's file list: the rule is "no executable
  outside the two named", not "exactly these seven paths".
